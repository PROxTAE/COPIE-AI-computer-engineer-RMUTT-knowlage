ฉันรับผิดชอบ P2 ของโปรเจกต์ COPIE ต้องทำงานตามแผนให้มากที่สุดและ commit โค้ดภายในวันอาทิตย์ที่ 27 ก.ย. 2026 (เวลาไทย) งานนี้ต้องเดินต่อเนื่องจนจบส่วนที่รับผิดชอบ ไม่หยุดหลังทำ PR แรก

ให้เปิดอ่านไฟล์ใน ZIP ที่แนบทั้งหมดโดยเริ่มจาก START_HERE.md, เอกสาร 00 กลาง, AI_EXECUTION_INSTRUCTIONS.md, 02_USER_SYSTEM.md, contract ทั้งสองฝั่ง และไฟล์ประกอบเฉพาะงาน (ภาพเป็นแบบหน้าตา ไม่ใช่ข้อมูลจริง) แล้วตรวจโค้ดใน repository ปัจจุบันก่อนแก้ อย่าทำงานซ้ำสิ่งที่มีอยู่แล้ว

เริ่มจาก PR แรก (`user/db-and-dev-auth`): ทำ models/DB, JWT และ /api/auth/dev พร้อม get_user_context/history stubs ตาม contract; ยังไม่ทำ Google Login UI ใน PR นี้
สิ่งที่ต้องส่งต่อให้ทีม: ส่ง get_user_context/history stub ให้ P3, Dev Login ให้ P8; PR ถัดไปทำ login/onboarding ให้ P1 ใช้

ทำงานตาม Phase ของแผน P2 ต่อเนื่องไปจนถึง Definition of Done โดยแยกเป็น PR เล็กตาม Branch / PR breakdown ในแผน อย่ารวมทุกอย่างใน PR เดียว หลังจบแต่ละ slice ให้ตรวจและสรุปผลเพื่อให้ฉัน commit/push/เปิด PR แล้วจึงไป slice ถัดไป ถ้างานใดต้องรอเพื่อน ให้ทำ stub/fixture ตาม contract เฉพาะระหว่างพัฒนา แจ้งว่ารอฟังก์ชันหรือข้อมูลอะไร แล้วทำงานส่วนอื่นต่อทันที

แก้เฉพาะไฟล์ที่แผนระบุว่าเป็น Ownership ของ P2 ถ้าต้องแก้ contract หรือไฟล์เจ้าของอื่น ให้เสนอผลกระทบและหยุดก่อนแก้ ห้ามสร้าง field/endpoint เอง ข้อมูลภาค รายวิชา หน่วยกิต และคะแนนต้องมีแหล่งจริงหรือสูตรตรวจได้; ใช้ mock/stub เฉพาะงานพัฒนาและ tests ห้ามปล่อย mock ไว้ใน flow demo จริง

ก่อนเริ่ม ให้สรุปสั้น ๆ ว่า (1) เข้าใจ scope/contract อย่างไร (2) ไฟล์ใดมีอยู่แล้วหรือยังขาด (3) จะทำไฟล์ใดใน PR นี้ แล้วลงมือทำและรันการตรวจ: cd backend แล้วรัน pytest ของ user และ ruff check .; แนบตัวอย่างคำตอบ /api/auth/dev

หลังแต่ละ slice รายงานไฟล์ที่แก้ ผลตรวจ หลักฐาน ข้อที่ยังรอคนอื่น และร่างข้อความ PR ตาม PR_TEMPLATE.md (PR แรกตัวอย่างชื่อ `feat(user): add dev auth and user models`, base `develop`, reviewer P3) พร้อมแนะนำ slice ถัดไปทันที อย่า commit, push, เปิด PR หรือ merge แทนฉัน; ฉันจะตรวจ diff และทำ Git เองภายในสุดสัปดาห์ ห้ามใส่ AI attribution, secret หรือไฟล์ตั้งค่าของ AI ใน repo
